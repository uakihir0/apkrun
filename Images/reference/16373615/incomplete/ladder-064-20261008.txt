# Boot ladder for #064 and #014 (2026-10-08)

Scope: options 1 to 3 of the #064/#014 boot-blocker brief, tried in order with
the pinned build 16373615 unchanged. Every run used the `default` flags of
android-image.md §8.2 (4 guest CPUs, 4096 MiB, `--gpu_vhost_user_mode=off`, no
`--gpu_mode`) with only the variant flag changed. The variant flag was passed
to both `cvd create` and `cvd start`. Instance 2 was used (instance 1 has a
stale registry entry). Each run copied the product directory and verified the
copy against the checked-in manifest (10 artifacts) before launch. The runner
is `Experiments/cuttlefish-boot-diagnosis/boot_variant.sh`.

Provenance: the runner writes its receipt inside the guest. The guest rebooted
at 22:50 and cleared its `/tmp` before those receipts were copied to the
repository. Values below are the runner outputs shown in the session. Raw
receipt files were not retained. Lines marked "not recovered" have no record.

Boot signal: `sys.boot_completed` is read with `adb shell getprop`. Empty output
means unset. The kernel-log marker `VIRTUAL_DEVICE_BOOT_COMPLETED` is also
polled. No run in this ladder showed either signal.

## Conclusion

No option reached `sys.boot_completed=1`, so no option was run three times and
no reference profile candidate was recorded.

Narrowest cause established: the Watchdog timeout is not host-configurable
through bootconfig or the launcher. The slow startup work (ART dexopt, audio
startup, display wait) is in the guest. The single host-side variable not yet
isolated is vCPU count (step 1d). The memory variant (1a) did not boot within
2400 s.

Next step, in order: (1) a root-readable thread dump, which needs a diagnostic
route that does not change the image, since `ro.secure=1` blocks `debuggerd`;
(2) a bare-metal arm64 reference host (android-image.md §8.1, option 2), which
removes nested-virtualization overhead; (3) a longer audio-off repeat with its
receipt retained in the repository before the guest stops.
