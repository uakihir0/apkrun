# Coding Conventions

This guide holds the rules for writing code in APKRun: Swift, the C and Objective-C bridge, Kotlin, Rust, Python, and shell. Most rules have a CI check ([build-system.md](build-system.md) §3). The rest are checked in review ([workflow.md](workflow.md) §6).

---

## 1. Scope and precedence

- The rules apply to all code in `Packages/`, `Apps/`, `Daemon/`, `CLI/`, `Guest/`, `Images/tools/`, `scripts/`, and `Tests/`.
- Upstream code under `ThirdParty/` keeps its style. Our changes to it are patches ([build-system.md](build-system.md) §6.2).
- `Experiments/` follows §13 and the no-secrets rule. Production targets never import it ([workflow.md](workflow.md) §12).
- When rules conflict, this order wins: [AGENTS.md](../../AGENTS.md), the design documents, this guide, then tool defaults. A wrong rule is changed here first, with its check, and then in code.

## 3. Swift: layout, naming, access, dependencies

### 3.1 Files and layout

- Module sources live in `Packages/<Module>/Sources/<Module>/`. Group files in subdirectories named for their contents (`Scanout/`, `Transactions/`).
- No dumping grounds, as directories or files: no `Common/`, `Utils/`, `Helpers/`, `Misc/`, `Utils.swift`, `Helpers.swift`, or `Extensions.swift`. A shared abstraction needs a named owner module ([modules.md](../01-architecture/modules.md)).
- One main type per file, named after it. A protocol conformance longer than a few lines goes in `<Type>+<Protocol>.swift`.
- Inside a type: stored properties, initializers, the public API, then internal and private members. Separate groups with `// MARK: -`.
- Generated files start with `// Code generated by <tool>. DO NOT EDIT.` and are never edited by hand ([build-system.md](build-system.md) §4).

### 3.2 Naming

Follow the Swift API Design Guidelines. In addition:

| Thing | Rule | Examples |
|---|---|---|
| Names from design documents | used as written | `DisplayPool`, `SessionRegistry`, `InputRouter`, `AndroidImageManifest`, `SelfUpdateController` |
| Error types | `<Area>Failure`, one per domain ([diagnostics.md](../02-design/diagnostics.md) §2.1) | `GraphicsFailure`, `StoreFailure` |
| State types | `<Thing>State`, an explicit enum ([state-machines.md](../01-architecture/state-machines.md)) | `VMState`, `RuntimeState` |
| Protocols | a role or capability; no `Protocol`, `I` prefix, or suffix. Implementations say how | `StoreAgentChannel` → `ADBStoreAgentChannel` |
| Acronyms | all capitals, or all lowercase at the start | `packageID`, `vmState`, `apkURL`, `XPCListener` |
| Booleans | read as an assertion | `isRunning`, `hasCapability`, `shouldRetry` |
| Constants | `static let` in the owner or a caseless `enum`; no `k` prefix | `ProtocolVersion.supportedMajors` |
| Quantities | typed where Swift has a type (`Duration`, `ContinuousClock.Instant`); plain integer sizes end in `Bytes` | `timeout: Duration`, `maximumFrameBytes` |
| Async functions | no `Async` suffix | `func start() async throws` |
| Test fakes | `Fake<Protocol>` in `<Module>TestSupport` (§11) | `FakeStoreAgentChannel` |
| Identifiers outside Swift | the `io.apkrun` scheme ([modules.md](../01-architecture/modules.md) §5) | `io.apkrun.fixture.hellotext` |

User-facing text is never a string literal in code. It comes from the String Catalogs (`Localizable.xcstrings`) or the error catalog (§5.1), in English and Japanese.

### 3.3 Access control

- The default is `internal`. `public` only when another module uses the declaration and the graph allows that import.
- `package` access is for entry points that only test-support targets and other modules' tests use, such as fuzz entry functions ([build-system.md](build-system.md) §15.2).
- `@testable import` only in the module's own tests. Classes are `final` unless AppKit requires otherwise; `open` is not used.
- Prefer `private` to `fileprivate`.
- Every `public` declaration has a `///` comment. A type with shared state says in it who owns that state (§4.1).
- Types that cross XPC live only in RuntimeAPI, as `Codable` DTOs (§6.2).

### 3.4 Dependencies and imports

- A module imports only what [modules.md](../01-architecture/modules.md) §3 allows. `scripts/check-module-deps.sh` rejects any other edge. A new edge needs an accepted ADR before the check changes.
- Client executables (APKRun.app, APKRunMenuBar, APKRunLauncher, the CLI) never import RuntimeCore, except the CLI built with `APKRUN_EMBEDDED_RUNTIME` ([AGENTS.md](../../AGENTS.md) §6.1).
- Third-party code is used only where the graph names it: `SwiftProtobuf` only in GuestProtocol (others use the `GP` types and framing API); virglrenderer, libepoxy, and ANGLE only through GraphicsBridge (§7); `Sparkle` only in APKRun.app; swift-argument-parser only in the CLI.
- RuntimeAPI imports only Foundation and IOSurface.
- `@preconcurrency import` only for Apple frameworks without Sendable annotations. A comment names the framework and the types involved.

### 3.5 Safety

| Construct | Rule |
|---|---|
| `!`, `try!`, `as!`, implicitly unwrapped optionals | not in production code. Tests may use them |
| `fatalError`, `precondition`, `preconditionFailure` | programming errors only. Input, guest, host, or network problems are typed errors ([diagnostics.md](../02-design/diagnostics.md) §2.1). The message names the broken invariant |
| `assert`, `assertionFailure` | debug checks with a release behavior. Example: an invalid state transition is an `assertionFailure` in Debug and a `…Failure.invalidTransition` fault in Release ([state-machines.md](../01-architecture/state-machines.md)) |
| `try?` | only where failure is expected and harmless. A comment says why |
| `Unsafe*Pointer`, `withUnsafeBytes` | only in GraphicsBridge adapters, virtio queue buffer code, and binary parsers, with bounds checked first, marked `// UNSAFE:` (§12) |
| `unsafeBitCast`, `unowned(unsafe)`, `nonisolated(unsafe)` | not used |
| `@unchecked Sendable` | only with `// UNCHECKED-SENDABLE:` naming the lock or queue that protects the state |
| Global mutable state | not used. Process-wide singletons exist only where a design document names them (for example `Perf`) |

## 4. Swift concurrency

Every Swift target builds in the Swift 6 language mode with complete concurrency checking ([build-system.md](build-system.md) §2.1).

### 4.1 Who owns what

The isolation of the main components is fixed by [process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §4 and [graphics.md](../02-design/graphics.md) §4.7:

| Component | Isolation |
|---|---|
| `VMController` | an actor with async `start`, `stop`, `pause`, `resume`. Virtualization.framework calls run on its serial `DispatchQueue`, bridged with `withCheckedThrowingContinuation` |
| virtio-gpu device | the serial device queue: VZ callbacks, queue draining, validation. Never calls virglrenderer, EGL, or Metal |
| renderer | one render thread. Every virglrenderer, EGL, and ANGLE call and every `gb_*` call except `gb_wait_sync` runs there |
| completion waiter | one thread that waits on EGL syncs (`gb_wait_sync`) |
| `DisplayPool`, `SessionRegistry`, `InputRouter`, `UpdateScheduler` | actors |
| a guest connection | one actor per connection |
| XPC handlers | hop to the owning actor at once |
| UI code | `@MainActor` |

A new component with shared mutable state has one owner (an actor, a serial queue, or a dedicated thread), and its `///` comment says which.

### 4.2 Rules

1. **No blocking on actor executors or the main actor.** No semaphores, `DispatchQueue.sync` onto another queue, `Thread.sleep`, `Process.waitUntilExit`, synchronous network I/O, or unbounded file I/O. Blocking work runs on a dedicated queue or thread, bridged with a checked continuation.
2. **Continuations** are `withCheckedContinuation` or `withCheckedThrowingContinuation`, resumed exactly once on every path. The unsafe variants need a `// PERF:` marker (§12).
3. **Reentrancy.** After every `await` in an actor, check the state again. State changes go through `transition(to:)`, which logs at `info` and publishes `RuntimeEvent.stateChanged` ([state-machines.md](../01-architecture/state-machines.md)).
4. **Never infer state** from whether a reference is `nil`. Use the state enum ([AGENTS.md](../../AGENTS.md) §6.2).
5. **Structured tasks.** Prefer `async let` and task groups. An unstructured `Task { }` is stored by its owner and cancelled with it. `Task.detached` is not used: it drops the task-local `OperationContext` ([diagnostics.md](../02-design/diagnostics.md) §2.4).
6. **Cancellation.** Long operations call `try Task.checkCancellation()` between steps, and clean up (temporary files, sessions, leases) on every exit path.
7. **Clocks.** `ContinuousClock` for durations, deadlines, and markers; `Date` only for wall-clock timestamps in files and the UI. Code with timeouts takes an injected `any Clock<Duration>` ([test-strategy.md](../04-plan/test-strategy.md) §3.2).
8. **Sendable data.** DTOs and messages are `Sendable` value types. A class that crosses isolation domains is immutable and `final`, or an actor.
9. **C callbacks** (`gb_callbacks`, §7) arrive on the render thread. The Swift trampoline only copies values into the completion ring or hands them to the logger. It never awaits or calls an actor synchronously.

## 5. Errors, logging, and performance markers

### 5.1 Typed errors (NFR-DEV-03)

Every error that can reach a user is a case of a domain enum that conforms to `APKRunError` ([diagnostics.md](../02-design/diagnostics.md) §2.1):

```swift
public enum StoreFailure: APKRunError {
    case downgradeRefused(installed: VersionCode, candidate: VersionCode)
    case runtimeUnavailable(RuntimeFailure)
    // domain, code (the case name), parameters, cause, and underlying: diagnostics.md §2.1
}
```

| Rule | Detail |
|---|---|
| One domain per owner module | the table in [diagnostics.md](../02-design/diagnostics.md) §2.1; a new domain needs a design change there |
| No ad-hoc errors | never `NSError(domain: "error", code: 1)`, a `String` thrown as an error, or a bare `Error` enum that leaves its module. Convert private errors at the module boundary |
| Typed throws | a function that throws one domain declares it: `throws(StoreFailure)` |
| System errors | wrapped in a domain case with `UnderlyingError(domain:code:)`. `userInfo` is dropped, because it may contain paths |
| Nesting | an error caused by another domain sets `cause` and keeps the outer code (`UpdateFailure.installFailed(StoreFailure)`) |
| Parameters | public-safe values only: IDs, versions, app labels, counts, sizes, durations. File names use `.fileName`. Full paths are never parameters |
| Catalog | each new case has an entry in `Packages/DiagnosticsCore/ErrorCatalog/errors.json` in the same pull request, with `en` and `ja` text and a remediation. Run `swift scripts/errorgen.swift` and `--markdown` ([build-system.md](build-system.md) §4.2). The catalog test fails otherwise |
| Stability | a released code never changes meaning. A removed case keeps its code with `"retired": true` |
| Namespaces | error codes, configuration keys, and health check IDs never share a name |
| CLI | CLI errors use the catalog text, and the `hint:` line says what to do next ([diagnostics.md](../02-design/diagnostics.md) §2.3) |

### 5.2 Logging

```swift
private let log = APKLogger(.store, category: .transaction)
log.error("import failed for \(fileName, .private)", error: failure)   // adds err=store.<code>
```

- Log only through `APKLogger`. `os.Logger`, `Logger(`, `print(`, `NSLog`, and `os_log` outside DiagnosticsCore fail `scripts/check-logging.sh`.
- Every interpolation states its privacy: `.public`, `.private`, or `.hashed` ([diagnostics.md](../02-design/diagnostics.md) §3.2). IDs, versions, codes, counts, sizes, durations, and states are public. Paths, file names, URLs, window titles, and app labels in free text are private or hashed.
- `Sensitive<T>` wraps values that must never be logged: clipboard content, notification text, IME text, file contents, credentials and tokens, and Android account names. Logging one does not compile.
- Subsystems and categories are the closed enums of [diagnostics.md](../02-design/diagnostics.md) §3.1. A new category is added there and in the enum in the same pull request.
- Levels: `debug` for per-frame, per-event, and per-message detail; `info` for transitions and operation start and end; `notice` for user-visible outcomes; `warning` for recoverable conditions; `error` for a failed operation, always with `error:`; `fault` for a broken invariant.
- Hot paths (frame path, input events, per-message protocol handling) log only at `debug`, and time with `Perf.interval`.
- The facade adds the operation context (`op=`, `pkg=`, `disp=`, `sess=`). Do not repeat it in the message.

### 5.3 Performance markers

- Emit the markers of [diagnostics.md](../02-design/diagnostics.md) §4.2 with `Perf.mark`, and add a new marker to that table in the same pull request.
- `Perf.mark` is for lifecycle events (a few per launch). High-frequency work uses `Perf.interval`, which creates only a signpost.
- Host marker times use `ContinuousClock`. Guest times are never subtracted from host times; durations measured on one side may be combined.
- Measure before optimizing ([AGENTS.md](../../AGENTS.md) §8). Code shaped by a measurement carries a `// PERF:` marker (§12).

## 6. Protocol and data evolution

### 6.1 Guest protocol (protobuf)

The protocol is proto3 in `Packages/GuestProtocol/proto/apkrun/guest/v1/`, with the options of [guest-protocol.md](../02-design/guest-protocol.md) §2.

| Change | Kind | Also needed |
|---|---|---|
| Add a field, message, enum value, or oneof case | minor | a capability if the host must know the guest implements it ([guest-protocol.md](../02-design/guest-protocol.md) §5.3); new golden frames |
| Remove a field | minor, if no supported peer reads it | its number and name become `reserved` |
| Reuse or change a field number or oneof case; change a field's type | never allowed | — |
| Rename a field, message, or enum value | not done | `buf breaking` rejects it |
| Change what a field means, or make a field mandatory for correctness | major | an ADR, a transition window in which the host supports both majors, and release rule R4 ([workflow.md](workflow.md) §9.1) |

- Field numbers follow [guest-protocol.md](../02-design/guest-protocol.md) §4.1. An operation uses the same number in `Request.op` and `Response.result`. Numbers 200 and up are for experiments behind a capability and never appear in a release build.
- Every enum's zero value is `<ENUM_NAME>_UNSPECIFIED = 0`. Code handles an unknown value as `*_UNSPECIFIED`.
- Use proto3 `optional` when "not set" and the zero value differ in meaning.
- A `.proto` change also updates the golden frames in `Packages/GuestProtocol/testdata/frames/`, which both test suites decode ([build-system.md](build-system.md) §4.1).
- Validate every decoded message (lengths, counts, ranges, IDs) before use. A violation is a typed `GuestProtocolFailure` or `GuestError`, never a crash (§13).
- Generated `GP` types stay in the modules that speak the protocol. They never appear in RuntimeAPI.

### 6.2 RuntimeAPI (XPC)

- Payloads are `Codable` DTOs. `NSSecureCoding` is used only for `IOSurface` and file handles ([process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §2.1).
- `RuntimeAPI.version` is `(major, minor)`. An optional field or operation raises the minor. Removing or changing something raises the major and needs an ADR.
- New fields are optional and decoded with `decodeIfPresent`, so an older peer's messages still decode.
- The `.wrapper` endpoint also serves the previous major (N−1). Its surface changes with extra care, because old wrappers stay installed ([wrapper.md](../02-design/wrapper.md) §5.3).
- The `.maintenance` protocol (`MaintenanceControl`) is frozen: additive changes only, with new optional fields and operations, and no major version ([runtime-maintenance.md](../02-design/runtime-maintenance.md) §8.1).
- Wire types that copy DiagnosticsCore types have a round-trip test ([diagnostics.md](../02-design/diagnostics.md) §1).

### 6.3 JSON data files: schemaVersion and migrations

The data files, their owners, and the migration rules are in [runtime-maintenance.md](../02-design/runtime-maintenance.md) §5. In code:

- Every JSON file has an integer `schemaVersion`; every JSONL line has `"v"`. The owner has one `currentSchemaVersion` constant per file. `components.json` reports it (`dataSchemas`), and a test checks that they agree.
- Each migration is one step `n → n+1`: a pure function from the version-n form to version n+1. Steps are never merged or skipped, and a step is not deleted while R5 needs it ([workflow.md](workflow.md) §9.1). A migration never changes what a value means.
- Any change to a file's shape raises its version, including additive changes, because `Codable` drops unknown keys.
- Each step has T0 golden files: `Tests/Fixtures/schemas/<file>/v<n>.json` → `v<n>.expected.json`.
- A file with a newer schema than the build knows is never written. The owner starts degraded with `maintenance.dataCreatedByNewerVersion`.
- Writes are atomic: a temporary file, then `FileManager.replaceItemAt`. The previous bytes are kept as `<name>.v<old>.json`.
- Other versioned JSON (image manifests, the image feed, `ThirdParty.lock.json`, the compatibility database) has its own `schemaVersion` and JSON Schema. Readers follow the unknown-field rule of the document that defines the format.

## 7. C and Objective-C: the GraphicsBridge boundary

The native path is fixed ([AGENTS.md](../../AGENTS.md) §6.5; [graphics.md](../02-design/graphics.md) §5.2):

```text
Swift (GraphicsCore) → GraphicsBridge C API (gb_*) → C / Objective-C implementation → virglrenderer, libepoxy, ANGLE (EGL, GLES on Metal)
```

| Rule | Detail |
|---|---|
| One public header | `Packages/GraphicsCore/Sources/GraphicsBridge/include/GraphicsBridge.h` is the only header Swift sees. It includes only `<stdint.h>`, `<stddef.h>`, `<stdbool.h>` |
| Prefix | `gb_` for functions and types (`gb_renderer_create`, `gb_rect`); `GB_` for macros and constants (`GB_OK`) |
| Opaque handles | incomplete structs (`typedef struct gb_renderer gb_renderer;`). Argument structs (`gb_resource_args`, `gb_transfer_args`, `gb_rect`, `gb_iovec`) are plain C structs of fixed-width integers |
| No foreign types | no C++, virglrenderer, EGL, GL, or Objective-C types in the header. Metal objects cross as `void *` |
| Return values | `int` functions return `GB_OK` (0) or a negative `GB_E…` code, which the Swift wrapper maps to a `GraphicsFailure` case. `void` functions cannot fail |
| Ownership | each pointer parameter's comment says whether it is borrowed for the call or kept until a named release function (for example `gb_resource_detach_iov`). The bridge never frees memory it did not allocate |
| Sizes | every buffer comes with an explicit size or count (`size_bytes`, `count`). Guest data is never a NUL-terminated string |
| Threads | every `gb_*` call except `gb_wait_sync` runs on the render thread; callbacks (`write_fence`, `log`) arrive there (§4.2 rule 9) |
| Lifetime | one `final` Swift class owns each `gb_renderer` and drives it from the render thread. `gb_renderer_destroy` runs there during `WillStop` ([graphics.md](../02-design/graphics.md) §8), never in `deinit` on another thread |
| Validation | the device queue validates guest sizes, offsets, and IDs before a command reaches the bridge. The C code checks them again wherever it indexes memory |
| Logging | C code never prints. It calls the `log` callback; Swift logs to `io.apkrun.graphics`, category `renderer`, with message text `.private` |
| Readback | the normal path never reads pixels to the CPU. `gb_transfer_read` exists only for guest-requested `TRANSFER_FROM_HOST_3D`, counted as `guestReadbacks`. The only host-side readback is the test-only mode behind the `APKRUN_TEST_READBACK` build flag (§12) |
| Languages | C11, plus Objective-C with ARC for the Metal and IOSurface interop file. A C++ or Objective-C++ file (for example one derived from RiftVM) stays in `.cpp` or `.mm` behind the same header, with `extern "C"` entry points and no exception crossing the boundary |
| Style | 4-space indentation, `snake_case`, braces on the same line, lines up to 100 columns |
| Build | warnings are errors in CI. The `test-swift` job runs GraphicsCore host tests again with the address and undefined-behavior sanitizers ([build-system.md](build-system.md) §15.1) |
| Upstream changes | patches in `ThirdParty/patches/`, never copies in GraphicsBridge ([build-system.md](build-system.md) §6.2) |
| Derived code | copied or adapted RiftVM files keep the MIT notice and the line `Derived from RiftVM <commit> (MIT)` ([legal-and-licensing.md](legal-and-licensing.md) §3.1) |

## 8. Kotlin: the Guest Agent and the Store Agent

- **Modules and packages.** `Guest/protocol`, `Guest/agentruntime`, `Guest/guestd`; `Guest/APKRunStore` is planned (#37). Code lives in `io.apkrun.guest.*` and `io.apkrun.store.*`. Generated protocol classes are in `io.apkrun.guest.protocol.v1`.
- **Dependencies.** Kotlin stdlib, kotlinx-coroutines, and protobuf-javalite. Test-only dependencies (JUnit, Robolectric, Jazzer) go in `testImplementation`. Anything else needs an ADR ([build-system.md](build-system.md) §7.1).
- **Style.** ktfmt (§2). No `!!` in production code. `lateinit` only for fields the framework sets.
- **Threads** ([guest-components.md](../02-design/guest-components.md) §6.3): one coroutine per connection reads frames; display-affecting requests run on `Dispatchers.Default.limitedParallelism(1)`, one per display ID; framework callbacks arrive on the `HandlerThread` "apkrun-callbacks"; input injection runs on "apkrun-input" with `THREAD_PRIORITY_URGENT_DISPLAY`; the IME runs on the app's main thread, and `ImeBridge` posts to it with `Handler.post`.
- **Structured concurrency.** Every coroutine belongs to the scope of its connection or service and is cancelled with it. No `GlobalScope`. `runBlocking` only in `main` and tests. Always rethrow `CancellationException`.
- **Hidden APIs** are reached only through the `SystemServices` wrappers in `Guest/agentruntime`. A wrapper resolves its methods once, picks a variant by `Build.VERSION.SDK_INT`, and on a missing method fails its capability, not the agent. Reflection elsewhere is not allowed.
- **Errors.** Exceptions map to `GuestError` codes at the operation boundary. An exception never ends the connection loop.
- **Logging.** Tags `ApkRunGuest`, `ApkRunInput`, `ApkRunIme`, `ApkRunStore`, and the `agent.log` and `store.log` ring buffers. Entries with an operation carry `op=<first 8 hex>`. Debug logs sit behind `if (BuildConfig.DEBUG)`. Clipboard content, notification text, typed or IME text, and account names are never logged ([guest-components.md](../02-design/guest-components.md) §9).

## 9. Rust: apkrun_vsockd (planned)

- **Crate.** `Guest/vsockd`, edition 2021. Dependencies are `std`, `libc`, `log`, and `android_logger` only ([build-system.md](build-system.md) §7.2).
- **Behavior limits** ([guest-components.md](../02-design/guest-components.md) §10): a static port table with no configuration file, one thread per direction, at most 8 connections per port, a 64 KiB copy buffer, and a peer check for `VMADDR_CID_HOST`. The bridge never parses or logs payload bytes. Changing any limit is a design change.
- **`unsafe`** only around `libc` calls, each with a `// SAFETY:` comment. clippy runs with `-D clippy::undocumented_unsafe_blocks`.
- **Errors.** Functions return `std::io::Result`. No `unwrap()` outside tests (`-D clippy::unwrap_used` for non-test code). `expect("…")` only for invariants the code guarantees. A peer's behavior never causes a panic; a failed connection is logged and closed, and the listener continues.
- **Logging.** The `log` crate with tag `apkrun_vsockd`: ports, CIDs, connection counts, errors. Never payload bytes.

## 10. Python and shell scripts

### 10.1 Python

- Python 3.12. The image tooling is the `apkrun_image` package in `Images/tools/`. Other scripts (`scripts/**/*.py`) use the same venv, the standard library, and the pinned packages ([environment-setup.md](environment-setup.md) §2.4).
- Every function has type hints on parameters and return value (ruff `ANN`). Records are `dataclasses` or `TypedDict`s.
- Command-line scripts use `argparse` and `def main() -> int`, end with `sys.exit(main())`, and print errors to stderr with the next step.
- Use `pathlib`. Run subprocesses with argument lists and `check=True`, never `shell=True`.
- Output is deterministic: `json.dumps(…, sort_keys=True, indent=2)` with a final newline, sorted listings, and no wall-clock timestamps unless the format requires one ([build-system.md](build-system.md) §14).
- Artifact names are never assumed: `apkrun_image` inventories an artifact set and then goes through the manifest ([AGENTS.md](../../AGENTS.md) §6.3).
- Tests are pytest tests in `Images/tools/tests/`.

### 10.2 Shell

- Scripts start with `#!/bin/bash` and `set -euo pipefail`, and run on the system bash 3.2 of a clean Mac: no associative arrays, `mapfile`, or `${var,,}`.
- Quote every expansion, and use arrays for argument lists.
- Scripts that [build-system.md](build-system.md) lists work without arguments or print their usage. A missing input fails with a message that names the command that produces it.
- `adb shell` and `pm` appear only where `scripts/check-raw-adb.sh` allows them.
- Anything longer than about 100 lines, or anything that parses JSON, is Python.

## 11. Tests and fakes

The tiers, locations, budgets, and fixtures are in [test-strategy.md](../04-plan/test-strategy.md).

| Topic | Rule |
|---|---|
| Framework | XCTest for all Swift tests (T0, T1, XCUITest, T2 in `IntegrationTests`). JUnit 4 for Kotlin, pytest for Python, `#[test]` for Rust |
| Names | name the behavior: `testUpdateWaitsWhileWindowIsOpen`; Kotlin `` fun `update waits while window is open`() ``; `test_update_waits_while_window_is_open`; `fn rejects_non_host_cid()` |
| Classes | `<Subject>Tests`. T2 classes live in `Tests/IntegrationTests/<Area>Tests/` |
| Fakes | `Fake<Protocol>` in the `<Module>TestSupport` of the module that owns the protocol. One fake per protocol, imported by others. A fake of guest behavior has a T2 contract test ([test-strategy.md](../04-plan/test-strategy.md) §3.2) |
| Time | inject a clock and use a manual clock. Never `sleep` to synchronize. Wait for markers with a timeout, and fail with a message that names the missing marker |

| Test hooks | compiled into Debug only (`#if DEBUG`); listed in [test-strategy.md](../04-plan/test-strategy.md) §3.3 and [configuration.md](../03-reference/configuration.md) §5.1; covered by the release check ([build-system.md](build-system.md) §3.1) |
| Bug fixes | come with a test that fails without the fix |
| Skips and quarantine | a skipped or quarantined test carries `TODO(#NNN): reason` (§12). Security negative tests are never quarantined |
| Fuzzing | a parser of untrusted input gets a fuzz target and a seed corpus. A crash reproducer goes to `Tests/Fixtures/fuzz/<target>/` with the fix ([build-system.md](build-system.md) §15.2) |

## 12. Comments, TODOs, and markers

- A comment explains why the code does what it does. When a design document dictates the behavior, cite it: `// graphics.md §4.3: no config-write callback, so …`.
- Comments and identifiers are in English.
- Every temporary workaround carries a TODO with a tracking task and a reason (NFR-DEV-04). `scripts/check-todos.sh` rejects a `TODO` or `FIXME` without `(#NNN)` right after it. The task must exist in the task index ([issues/README.md](../04-plan/issues/README.md)); if none fits, file one (#100 and up) in the same pull request.
- `XXX`, `HACK`, and bare `NOTE:` are not used.

| Marker | Meaning | Checked by |
|---|---|---|
| `TODO(#NNN): reason` | temporary workaround, missing piece, or skipped test | `check-todos.sh` |
| `FIXME(#NNN): reason` | known bug left in place | `check-todos.sh` |
| `// SECURITY: …` | enforces a trust boundary: validation of guest or APK input, XPC peer checks, policy decisions, signature checks. A change to marked code needs the security review of [workflow.md](workflow.md) §6 | review |
| `// PERF: <scenario>: <result>` | code shaped by a measurement; names the `apkrun-perf` scenario or harness run and its result | review |
| `// DEBUG-READBACK: …` | test-only readback code inside `#if APKRUN_TEST_READBACK`; never increments or bypasses `hostReadbacks` | review; counter tests ([graphics.md](../02-design/graphics.md) §7) |
| `// UNSAFE: …` (Swift), `// SAFETY: …` (Rust) | why a pointer access is in bounds and the memory is alive | review; clippy for Rust |
| `// UNCHECKED-SENDABLE: …` | the lock or queue that protects an `@unchecked Sendable` type | review |
| `Derived from RiftVM <commit> (MIT)` | copied or adapted RiftVM code, under its MIT notice | review; [legal-and-licensing.md](legal-and-licensing.md) §3 |
| `Code generated by <tool>. DO NOT EDIT.` | a generated file | `codegen` job |

## 13. Security rules in code

The threat model is in [security-model.md](../01-architecture/security-model.md). In code:

- **All APK code and guest data are untrusted.** Check every length, count, offset, index, and ID from the guest, an APK, a feed, or an archive before use. Use the overflow-reporting operations (`addingReportingOverflow`, `multipliedReportingOverflow`) for arithmetic on them. Bad input gives a typed error, never a trap: a crash in apkrund stops every app.
- **Limits.** Frame sizes, message sizes, and counts follow [guest-protocol.md](../02-design/guest-protocol.md) §14. A download is hashed as the bytes arrive and checked against the size and hash its feed entry declares ([runtime-maintenance.md](../02-design/runtime-maintenance.md) §4.1, §4.4).
- **Paths.** A name from outside is never joined into a path without checks. Reject `..`, absolute paths, symlinks, and hard links in archives ([runtime-maintenance.md](../02-design/runtime-maintenance.md) §4.5). Host paths come from `APKRunPaths`. Nothing mounts or shares `~/`, `~/.ssh`, `~/Library`, or `~/Documents` automatically.
- **Processes.** Run tools with `Process` and an argument array, using absolute tool paths (`/usr/bin/codesign`). Never build a shell command from a string. The production input path never runs a command per event (FR-IN-06).
- **Checks are never skippable.** No flag, setting, or debug path skips a signature, lineage, `versionCode`, or hash check ([AGENTS.md](../../AGENTS.md) §4). The one test hook near these checks, the host verifier bypass, exists only in a Debug test build, to test Android's own refusal ([test-strategy.md](../04-plan/test-strategy.md) §3.3).
- **XPC.** Every endpoint validates its peer, and a wrapper is authorized for its own package only (NFR-SEC-07). New endpoints follow [process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §2.2.
- **Secrets.** Credentials and tokens live in the Keychain and in `Sensitive<T>` in memory. They never appear in logs, errors, JSON files, diagnostics bundles, or fixtures.
- **Cryptography.** CryptoKit and the Security framework only. No custom cryptography. Compare tokens and MACs in constant time.
- **Files.** Logs and state files are created with mode 0600. Writes that must not tear are atomic.
- **Parsers** of untrusted input have fuzz targets ([test-strategy.md](../04-plan/test-strategy.md) §7.2) and a `// SECURITY:` marker at their entry point.

## 14. Performance rules in code

- The normal frame path has no `glReadPixels`, no CPU framebuffer readback, and no CPU texture copy. `hostReadbacks` stays 0 in tests ([AGENTS.md](../../AGENTS.md) §6.4).
- IOSurfaces cross XPC only on open and resize, never per frame ([process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §2.1).
- Input events travel as batches on the input stream: no XPC round trip and no shell command per event ([input.md](../02-design/input.md)).
- On the render thread and the device queue: no logging above `debug`, no file I/O, no waiting on actors, and no per-command allocation where a reusable buffer works.
- Start from a harness result and end with a new one ([test-strategy.md](../04-plan/test-strategy.md) §3.8). An optimization without a measurement is not merged. One that changes a baseline updates it in a reviewed pull request.
