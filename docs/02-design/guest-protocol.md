## 1. Scope and principles

GuestProtocol is the only interface between host code and APKRun's guest components. The GuestProtocol module owns the message definitions, the framing codec, and the version constants. It has no business logic. RuntimeCore, APKStoreCore, and IntegrationCore build typed channels on top of it ([../01-architecture/modules.md](../01-architecture/modules.md) §2).

Principles:

1. **One schema.** The `.proto` files in `Packages/GuestProtocol/proto/` are the source of truth for both sides.
2. **Host initiates, guest serves.** The host opens every connection and sends every request. The guest sends responses and events. The guest never waits for the host, so a slow or absent host cannot block Android threads.
3. **Snapshot plus events.** After every (re)connect the host reads a snapshot and then applies events. The guest does not replay missed events.
4. **Validate everything on both sides.** Messages from the guest are untrusted input to apkrund ([../01-architecture/security-model.md](../01-architecture/security-model.md)). Messages from the host are checked by the agents too.
5. **No per-event process spawning.** Every production operation is one message on an open stream (FR-IN-06, NFR-PERF).

## 4. Framing

```text
frame := length:uint32 (big-endian) || Envelope (protobuf binary, `length` bytes)
```

- The maximum `length` is 4 MiB (4 194 304). A larger length closes the connection with `frameTooLarge`. A length of 0 is invalid.
- Frames are written whole. The writer never interleaves two frames on one connection.
- Readers use a fixed 64 KiB read buffer plus an allocation up to the frame length. They never allocate on the basis of an unvalidated length above the limit.
- `FrameCodec` (Swift) and `io.apkrun.guest.protocol.FrameCodec` (Kotlin) are pure functions over byte buffers. They share golden test vectors (§16).

### 4.1 Envelope

```proto
message Envelope {
  uint64 id = 1;            // per connection and per sender, starts at 1, strictly increasing
  uint64 reply_to = 2;      // set on `response`: the id of the request
  string operation_id = 3;  // host OperationID for log correlation (DiagnosticsCore); optional
  oneof body {
    Hello hello = 10;
    HelloAck hello_ack = 11;
    Request request = 12;
    Response response = 13;
    Event event = 14;
    Cancel cancel = 15;
    InputBatch input_batch = 20;
    InputAck input_ack = 21;
    ImeCommand ime_command = 22;
    ImeState ime_state = 23;
    BulkFrame bulk = 30;
  }
}

message Request {
  uint32 timeout_ms = 1;    // the agent gives up after this; the host waits timeout_ms + 1000
  oneof op { /* §7.1 and §11.1 */ }
}

message Response {
  oneof result {
    GuestError error = 1;
    /* one result message per op, same field number as the op in Request */
  }
}

message Event {
  uint64 seq = 1;           // per connection, starts at 1; gaps are a protocol violation
  oneof kind { /* §8 and §11.2 */ }
}

message Cancel { uint64 target_id = 1; }   // best effort; the response still arrives (error CANCELLED or the result)
```

Field numbering rule: an operation uses the same field number in `Request.op` and in `Response.result`. Number ranges:

| Range | Area |
|---|---|
| 10–39 | core and control (Guest Agent) |
| 40–59 | integration, host → Guest Agent |
| 60–69 | integration, Guest Agent → host (file operations on the bulk channel, §7.5) |
| 70–79 | system and diagnostics (Guest Agent) |
| 100–139 | Store Agent |
| 200+ | reserved for experiments behind a capability, never in a release build |

## 5. Handshake, versions, capabilities

### 5.1 Hello

The server (agent) speaks first after the connection is established. The message definitions match [../01-architecture/process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §3.3.

```proto
message ProtocolVersion { uint32 major = 1; uint32 minor = 2; }

message Hello {
  ProtocolVersion protocol_version = 1;
  AgentInfo agent = 2;                    // kind (GUEST_AGENT, STORE_AGENT, GUEST_IME), version_name, version_code, build_id
  string runtime_image_version = 3;       // ro.boot.apkrun.image: the imageVersion that ImageCore wrote into bootconfig for this boot (android-image.md §6.2)
  AndroidInfo android = 4;                // sdk_int, release, build_fingerprint, build_type (user/userdebug)
  repeated string capabilities = 5;       // §5.3
  ChannelKind channel = 6;                // which channel this server believes it is (§3)
  AgentMode mode = 7;                     // DEVELOPMENT_SHELL (app_process under shell) or PRIVILEGED_APP
}

message HelloAck {
  oneof outcome { Accepted accepted = 1; Rejected rejected = 2; }
  ProtocolVersion host_protocol_version = 3;
  bytes session_token = 4;                // 16 random bytes, see §5.4
  repeated string enabled_capabilities = 5;
  string host_version = 6;                // APKRun version, for guest logs
}
message Accepted {}
message Rejected { RejectReason reason = 1; string detail = 2; }   // INCOMPATIBLE_VERSION, WRONG_CHANNEL, BAD_TOKEN, DUPLICATE_SESSION
```

Timeouts: the host waits 5 s for `Hello` after connecting and closes the connection otherwise. The agent waits 5 s for `HelloAck`. No other frame may be sent before the handshake completes.

### 5.2 Version rules

| Situation | Result |
|---|---|
| Same major, any minor | accepted. Features are negotiated through capabilities |
| Different major | the host sends `Rejected{INCOMPATIBLE_VERSION}` and closes. Health marks the agent `incompatible`. The user sees `GuestProtocolFailure.incompatibleVersion` with the remediation "Update APKRun" (agent newer) or "Update Android" (agent older) (NFR-REL-04) |
| Unknown request op (older agent) | the agent answers `GuestError{UNSUPPORTED}`. The host treats a missing capability the same way before sending |
| Unknown event kind (newer agent) | the host ignores it and counts `guest.unknownEvent` |
| Unknown enum value | treated as `*_UNSPECIFIED` |

- The host supports protocol major **1** in v1. The supported range is a constant in `ProtocolVersion.swift` (`supportedMajors = 1...1`).
- Runtime images declare the agent protocol range in the manifest (`requirements.guestProtocol`, [android-image.md](android-image.md) §12.1). ImageCore refuses to activate an image whose range does not intersect the host's range, so the incompatibility is caught before boot. The handshake check is the second line of defense.
- Development (stock image): the host carries the matching Guest Agent APK in its bundle (`APKRun.app/Contents/Resources/guest/apkrun-guest.apk`). It reinstalls it when the installed `versionCode` differs ([guest-components.md](guest-components.md) §3), so development mismatches are corrected automatically.

Implementation (#033): the host side is `GuestHandshake` in `Packages/GuestProtocol`, and the agent side is `AgentHandshake` in `Guest/protocol`. The version and channel rules of this table have T0 tests in `HandshakeTests.swift` and `AgentHandshakeTest.kt`. The unknown-op and unknown-event rules are tested with the agent and the connection (#072, #034). The host's major version is checked by the agent too, so a host with major 2 fails the handshake on the agent side with the same typed `incompatibleVersion`.

Evolution rules (checked in review and by `buf breaking`):

- Never change or reuse a field number or a oneof case. Removed fields become `reserved`.
- Adding a field, message, enum value, or oneof case is a minor change. If the host must know whether the guest implements it, it also gets a capability.
- Changing the meaning of an existing field, or making a new field mandatory for correctness, is a major change. It needs an ADR and a transition window in which the host supports both majors.

### 5.4 Session token and stream binding

- The host creates a new random `session_token` for each **control** connection (guest control and store control) and sends it in `HelloAck`.
- The secondary connections of the same agent (input, bulk, artifacts, development IME) receive the same token in their `HelloAck`. The agent rejects a secondary connection with `BAD_TOKEN` when the token does not match its current control session.
- When the control connection closes, the agent closes that session's secondary connections. It resets input state ([input.md](input.md) §7.3) and aborts bulk transfers. Android-side settings (density, IME policy) stay as they are. The host re-applies them after the next snapshot.
- A second control connection while one is open is rejected with `DUPLICATE_SESSION`, unless the old one has been silent for more than 15 s. In that case the agent closes the old one and accepts the new one (this covers a crashed apkrund whose socket was not closed cleanly).
- Who enforces each rule (#033, [implementation-review.md](../04-plan/implementation-review.md) IR-262). The agent sends `Hello` first, and `Hello` has no token field. A `Rejected` reason can only be sent by the host, inside `HelloAck`. So the host enforces the major version and the channel, and it answers with `Rejected`. The agent enforces `BAD_TOKEN` and `DUPLICATE_SESSION` on its own control session. It refuses the connection by closing it and logs the reason, and it does not send a `Rejected`.

## 6. Requests, events, and liveness

- **Pipelining:** the host may have up to 64 requests in flight per control connection. Responses may arrive in any order. The agent processes requests concurrently unless an operation says otherwise. Operations on the same display (`SetDisplayPolicy`, `LaunchApplication`, `ClearDisplay`, `MoveTaskToDisplay`) are serialized per display inside the agent.
- **Default timeouts** (host side, `Request.timeout_ms`): 5 s. `LaunchApplication` 15 s, `ClearDisplay` 5 s ([display-and-windowing.md](display-and-windowing.md) §3.4), `Shutdown` 20 s, `CollectDiagnostics` 60 s, `CommitInstall` 120 s. A timeout on the host produces `GuestProtocolFailure.timeout(operation)`. The connection stays open.
- **Events** are delivered in order per connection. Consumers are sequenced: a response to a request is sent only after all events caused by earlier requests. For example, after `SetDisplayPolicy` returns, the matching `DisplayChanged` (new density) has already been sent.
- **Keepalive:** the host sends `Ping` every 5 s on each control connection. Three consecutive missed `Pong`s (15 s) mark the agent `unresponsive` in health. The host closes the connection and reconnects with backoff (100 ms doubling to 2 s, [../01-architecture/process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §3.1). Secondary connections have no pings. They follow the control connection.
- **Resync:** after every control handshake the host sends `GetSnapshot` before anything else and replaces its view of guest state with the result. Events received before the snapshot response are buffered and applied afterwards if their state is newer (display and task events carry the IDs needed to deduplicate).

### 7.5 Agent → host file operations (`files.shared.v1`)

These are the only requests that the agent sends to the host. They serve `MacFilesProvider`, the Android document provider for the Mac shared folders ([desktop-integration.md](desktop-integration.md) §6.4). They travel on the guest bulk channel (6102), so file data never delays control traffic. The connection is still opened by the host ([../01-architecture/process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §3.1). Only the direction of the request changes.

### 8.2 Display event rules

- `DisplayAdded` is sent once for every non-private display that Android reports through `DisplayManager.DisplayListener.onDisplayAdded`. Display 0 is included in the snapshot.

### 8.3 Task event rules

- The agent uses `ITaskStackListener` (task created, removed, moved to front, display changed) and confirms with `IActivityTaskManager.getTasks`. `TaskChanged` is coalesced per task over 16 ms.

The semantics are in [input.md](input.md). The wire messages are:

```proto
  uint64 batch_seq = 1;
  int32 display_id = 2;           // stamped by InputRouter, never by the wrapper

  bool ack_requested = 4;         // every 32nd batch (input.md §8)
  repeated InputEvent events = 5; // at most 256 per batch

  uint64 host_time_nanos = 1;     // relative spacing is preserved by the injector

message ImeCommand {
  uint64 seq = 1;
  int32 display_id = 2;
  oneof kind {
    string commit_text = 10;                       // at most 4 KiB UTF-8
    Composing set_composing = 11;                  // text, selection_start, selection_end (relative to the text)
    FinishComposing finish_composing = 12;
    KeyEvent key = 13;                             // sent through InputConnection.sendKeyEvent
    int32 editor_action = 14;                      // EditorInfo.IME_ACTION_*

  }

message ImeState {                                 // guest → host; never contains the field's text
  bool editor_focused = 1;
  int32 display_id = 2;
  string package = 3;
  int32 input_type = 4;
  int32 ime_options = 5;
  int32 selection_start = 6;
  int32 selection_end = 7;

}
```

- The input stream carries no request/response pairs. Validation failures in a batch drop the offending event and are reported as a count in the next `InputAck` and in `Health.input`. They do not close the stream (§12.2 lists what does).

## 10. Bulk and artifact streams

```proto
message BulkFrame {
  uint64 transfer_id = 1;         // host-allocated IDs are even, agent-allocated IDs are odd
  oneof kind {
    BulkBegin begin = 10;         // kind, name, mime_type, size, sha256 (optional here), context (e.g. install_id)
    bytes chunk = 11;             // at most 1 MiB, in order
    BulkEnd end = 12;             // sha256 (required if not given in begin)
    BulkAck ack = 13;             // receiver → sender after end: OK, HASH_MISMATCH, TOO_LARGE, REJECTED
    BulkAbort abort = 14;         // either side; reason
  }
}
```

- A transfer is announced on the control channel (for example `ImportFiles` lists transfer IDs, `CollectDiagnostics` returns them). The data then flows on the bulk stream in either direction. At most 4 transfers are interleaved per stream, chunk by chunk.
- Limits: 2 GiB per transfer. The receiver writes to a temporary file (host: under `~/Library/Caches/io.apkrun.APKRun/transfers/`; guest: the agent's cache directory, or directly into a `PackageInstaller` session for install artifacts, §11.3). Incomplete transfers are deleted when the stream closes.
- Flow control is the stream's own (vsock or TCP back-pressure). Senders do not read whole files into memory.
- The artifact stream (6111) uses the same messages with the Store Agent. Kinds there: `INSTALL_ARTIFACT` (host → guest) and `ICON_LAYER` (guest → host).

### 11.3 InstallRequest and artifact streaming

```proto
message InstallRequest {
  string expected_package = 1;
  int64 expected_version_code = 2;            // 0 = do not check
  repeated bytes expected_signer_sha256 = 3;  // current signer certificate digests from the host's verification
  InstallMode mode = 4;                       // INSTALL_NEW, UPDATE, REINSTALL
  bool request_update_ownership = 5;          // SessionParams.setRequestUpdateOwnership (API 34)
  bool allow_downgrade = 6;                   // always false in v1; the field exists so the refusal is explicit
  repeated ArtifactSpec artifacts = 7;        // name ("base", "split_config.arm64_v8a", …), size, sha256
  int32 install_reason = 8;                   // PackageManager.INSTALL_REASON_USER
  int32 package_source = 9;                   // PackageInstaller.PACKAGE_SOURCE_OTHER
  bool enable_rollback = 10;                  // SessionParams.setEnableRollback(true, ROLLBACK_DATA_POLICY_RETAIN); UPDATE mode only
}
```

1. `BeginInstall` creates a `PackageInstaller` session (`MODE_FULL_INSTALL`) and returns `install_id`. `request_update_ownership` needs `store.ownership.v1` and `enable_rollback` needs `store.rollback.v1`. When a field is set without its capability, or `enable_rollback` is set with a mode other than `UPDATE`, the agent answers `INVALID_ARGUMENT`.
2. The host streams each artifact on 6111 with `BulkBegin{kind: INSTALL_ARTIFACT, context: install_id, name, size, sha256}`. The agent writes the chunks directly into `session.openWrite(name, 0, size)` and hashes them as it goes. A hash mismatch aborts the session and answers `BulkAck{HASH_MISMATCH}`.
3. `CommitInstall`. Before committing, the agent checks the staged package with Android's own parser against `expected_package`, `expected_version_code`, and `expected_signer_sha256` (defense in depth; the host checked the same things before). A mismatch finishes with `INVALID` and a message.
4. `InstallFinished` reports the outcome from the session's status receiver. The Store Agent holds `INSTALL_PACKAGES` as a privileged app, so `STATUS_PENDING_USER_ACTION` is not expected. If it happens, the agent abandons the session and reports `USER_ACTION_REQUIRED` rather than showing UI on a display the user may not see.

Sessions that are not committed within 10 minutes, or whose control connection closes, are abandoned by the agent.

## 12. Errors

### 12.1 GuestError

```proto
message GuestError {
  GuestErrorCode code = 1;
  string message = 2;                  // English, for developers and logs; no user data
  map<string, string> detail = 3;      // for example "android_exception" → class name, "status" → code
}

enum GuestErrorCode {
  GUEST_ERROR_CODE_UNSPECIFIED = 0;
  INVALID_ARGUMENT = 1;
  NOT_FOUND = 2;                       // package, display, task, notification key, transfer
  ALREADY_EXISTS = 3;
  PERMISSION_DENIED = 4;               // Android refused (SecurityException)
  FAILED_PRECONDITION = 5;             // e.g. boot not completed, display being cleared
  UNAVAILABLE = 6;                     // a system service is not ready
  TIMEOUT = 7;
  CANCELLED = 8;
  UNSUPPORTED = 9;                     // capability not enabled, or not possible in this AgentMode
  RESOURCE_EXHAUSTED = 10;             // too many in-flight requests or sessions
  INTERNAL = 11;
}
```

On the host, `GuestError` becomes `GuestProtocolFailure.remote(code, message, operation)`. Callers translate the cases they understand into their own domain (for example `NOT_FOUND` on `LaunchApplication` → `RuntimeFailure.packageNotInstalled`). The mapping is listed in [../03-reference/error-catalog.md](../03-reference/error-catalog.md).

### 12.2 Protocol violations

These close the connection and are logged with the Envelope id (never the payload):

- a frame that is too large, empty, or does not decode;
- a body that is not allowed on the channel (§3), or any frame before the handshake;
- a non-increasing `Envelope.id` or a gap in `Event.seq`;
- a `response` whose `reply_to` does not match an outstanding request.
- a `request` from the agent on any channel other than guest bulk, or with an operation outside 60–69 (§7.5).

The host reports `GuestProtocolFailure.malformedFrame` and reconnects with backoff. Five violations within 10 minutes stop reconnecting, and health `agent.guest` or `agent.store` fails with `runtime.requiredAgentUnavailable` ([runtime-daemon.md](runtime-daemon.md) §12). This keeps a looping failure from filling the logs.

### 12.3 Host error domain

`GuestProtocolFailure` cases: `incompatibleVersion(host, guest)`, `handshakeFailed(reason)`, `handshakeTimedOut`, `disconnected`, `timeout(operation)`, `remote(code, message, operation)`, `frameTooLarge`, `malformedFrame`, `capabilityMissing(capability)`, `agentUnavailable(kind)`. Codes and remediations are in [../03-reference/error-catalog.md](../03-reference/error-catalog.md).

## 13. Host-side API (GuestProtocol + RuntimeCore)

### 13.1 Connection layer

```swift
public enum GuestEndpoint: Sendable, Hashable {
    case guestControl, guestInput, guestBulk, storeControl, storeArtifacts, developmentIME
}

public protocol GuestTransport: Sendable {
    func open(_ endpoint: GuestEndpoint) async throws -> any GuestByteStream
}

public struct VsockGuestTransport: GuestTransport { /* VZVirtioSocketDevice.connect(toPort:), ports from process-model §3.1 */ }
public struct ADBForwardGuestTransport: GuestTransport { /* §13.2 */ }

public actor GuestConnection {
    public init(endpoint: GuestEndpoint, transport: any GuestTransport, token: SessionToken?)
    public func open() async throws -> GuestHello                        // handshake, §5
    public func send<Op: GuestOperation>(_ op: Op, timeout: Duration?) async throws -> Op.Result
    public func send(frame: GPEnvelope) async throws                     // input and bulk streams
    public nonisolated var events: AsyncStream<GPEvent> { get }
    public func close() async
}
```

- `GuestOperation` is a small protocol implemented by one struct per operation. It pairs the request oneof case with its result type, so call sites are typed and the numbering rule (§4.1) is checked in one place.
- `GuestAgentSupervisor` (RuntimeCore, actor) owns the control, input, and bulk connections of the Guest Agent. It does the reconnection, keepalive, and resync (§6), and it exposes typed facades: `DisplayControlChannel` ([display-and-windowing.md](display-and-windowing.md) §3.1), `AndroidControlChannel` (launch, stop, tasks, packages, health, shutdown), the input sink used by `InputRouter`, and `IntegrationChannel`.
- `StoreAgentSupervisor` does the same for the Store Agent and implements `StoreAgentChannel` for APKStoreCore.

### 13.2 Development transport (ADB forward)

- `ADBForwardGuestTransport` runs `adb -s 127.0.0.1:6520 forward tcp:0 localabstract:<name>` (the `adb` of the developer's platform-tools, [../05-development/environment-setup.md](../05-development/environment-setup.md)). It reads the allocated port from stdout and connects to `127.0.0.1:<port>`. The forward is removed with `adb forward --remove tcp:<port>` when the stream closes. Forwards left over from a crash are removed at startup (`adb forward --list`, entries whose remote starts with `localabstract:apkrun-`).
- This is one `adb` process per **connection**, not per message. It satisfies FR-IN-06.
- The ADB implementation of `StoreAgentChannel` (`ADBStoreAgentChannel`) covers stock images: `adb install-multiple -r --no-streaming` (the `-g` flag is not used), `pm uninstall` (`-k` to keep data), and metadata from the Guest Agent's `QueryPackage`. It cannot set update ownership, enable Android rollbacks, inspect archives, or render icons. APKStoreCore treats those as capabilities that are missing (`capabilityMissing`), not as errors. On debuggable images (`ro.debuggable=1`, the stock `userdebug` image) it offers rollback as a downgrade reinstall, `adb install-multiple -r -d` ([package-store.md](package-store.md) §7.3).

### 13.3 Which implementation is used

| Build and image | Guest Agent | Store Agent |
|---|---|---|
| M3–M4, stock image | `ADBForwardGuestTransport` | `ADBStoreAgentChannel` |
| M4, stock userdebug image with the bridge pushed and run as root (#034 validation only) | `VsockGuestTransport` | `ADBStoreAgentChannel` |
| M5+, custom image | `VsockGuestTransport` | `VsockGuestTransport` (store endpoints) |
| M5+, custom image, developer mode | vsock by default. `apkrun dev … --guest-transport adb` forces ADB for debugging | same |

## 14. Security and limits

| Limit | Value | Enforced by |
|---|---|---|
| Frame size | 4 MiB | both codecs |
| In-flight requests per control connection | 64 (`RESOURCE_EXHAUSTED` above) | agent |
| String fields | 64 KiB unless stated (clipboard 1 MiB, IME commit 4 KiB, notification title/text 256/2048 characters) | both sides; longer strings are truncated with a flag where the schema has one, otherwise rejected |
| Repeated fields | 4096 elements (input batch 256) | both sides |
| Transfer size | 2 GiB | bulk receivers |
| Agent → host file operations | 16 in flight, 1 MiB per read or write, 64 open handles per package | host (§7.5) |
| Connections per agent | 1 control session plus its secondary streams | agent (§5.4) |

- The agents authenticate peers with `SO_PEERCRED` ([../01-architecture/process-model-and-ipc.md](../01-architecture/process-model-and-ipc.md) §3.1). The protocol adds the session token so that only streams opened by the same host session are bound together.
- Package names, URLs, paths, and content URIs from the guest are validated on the host before use: package names against the Android package-name grammar, URLs limited to `http`, `https`, and `mailto` for `OpenUrlOnHost`, and shared-folder paths resolved inside their root ([desktop-integration.md](desktop-integration.md) §6.4, §7.2).
- Logs contain operation names, IDs, sizes, and error codes. Clipboard content, notification text, and typed text are never logged at any level. Input events and file names appear only at debug level in development builds ([diagnostics.md](diagnostics.md) §3.4).
- The Swift and Kotlin decoders are fuzz targets (#091): libFuzzer through a Swift fuzz harness on the host, and Jazzer for the Kotlin frame decoder and the injector's batch validator.

3. `FrameCodec` in Swift and Kotlin. Golden frames in `testdata/frames/` (one per body kind, plus invalid frames: oversize length, zero length, truncated body). Both test suites decode all of them and re-encode the valid ones byte for byte.

5. Acceptance: schemas compile for the host (`swift build`) and the guest (`./gradlew :guestd:assemble`). The version mismatch behavior is documented (§5.2) and covered by a T0 test (a fake agent sending major 2 is rejected with `incompatibleVersion`).

### #034 Full Guest Agent protocol and vsock transport (M4)
