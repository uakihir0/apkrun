5. Dependencies

- The image's EGL module (libEGL_emulation.so) has DT_NEEDED entries libcutils.so,
  libdrm.so, libOpenglCodecCommon.so, libOpenglSystemCommon.so, liblog.so,
  libnativewindow.so, libsync.so, libc++.so, libc.so, libm.so, and libdl.so.
  libcutils.so, libdrm.so, libOpenglCodecCommon.so, and libOpenglSystemCommon.so
  are in vendor_a /lib64. liblog.so, libnativewindow.so, libsync.so, and libc++.so
  are in system_a /system/lib64. libc.so, libm.so, and libdl.so there are symbolic
  links, which dump.erofs lists as type 7.
- The pinned root Android.bp defines mesa_platform_virtgpu, which whole-links
  platform_virtgpu_drm (src/gfxstream/guest/platform/drm/Android.bp). That module
  declares the shared libraries libdrm and libzstd, and on Android also libcutils,
  libhardware, liblog, libnativewindow, and libsync. mesa_platform_virtgpu itself
  declares libdrm, and on Android libsync. mesa_gfxstream_guest_iostream declares
  liblog. The tree also names libzstd in its util and loader modules
  (src/util/Android.bp, src/loader/Android.bp).
- Present in the image: libdrm.so, libcutils.so, and libhardware.so (vendor_a
  /lib64); liblog.so, libnativewindow.so, and libsync.so (system_a).
- Missing from the image: libzstd. No partition contains a zstd library; the
  listings have no entry that matches "zstd".
- Result: the mesa_platform_virtgpu closure of this tree needs libzstd, which the
  image does not contain. That closure is the gfxstream and virtgpu platform path,
  not the virgl gallium driver, which has no Android.bp in this tree (IR-440). So
  whether a virgl EGL build needs libzstd is not established. The other
  whole-static members of mesa_platform_virtgpu (for example platform_virtgpu,
  vulkan_util, and libvirtgpu_kumquat_ffi) were not traced, so the dependency list
  is incomplete.

6. Result

- Build 16373615 contains no Mesa EGL, GLES, gallium, or Mesa gbm library. Its
  system EGL and GLES set includes the ANGLE builds libEGL_angle.so and
  libGLESv2_angle.so (libEGL_angle.so needs libGLESv2_angle.so). The vendor set
  has the emulation libraries. This agrees with IR-185 and IR-244 for the loader
  paths.
- The pinned source defines no module that would install a Mesa EGL, GLES, or
  virgl library. Pinning it therefore does not supply the libraries that
  ro.hardware.egl=mesa loads.
